## 5. What went well and why

- **Probe the real runtime before designing.** A one-turn Codex and Claude probe exposed every mismatch in the offline design (frame sizes, `emittedAtMs`, output volume, timeouts). Keep doing a minimal live probe first.
- **Fakes shaped after observed traffic** let every live path be tested offline and made the orchestrator, roster and UI tests deterministic.
- **Evidence discipline**: receipts bound to a source hash that fails if the tree changes mid-run caught real mistakes (editing during a live gate) instead of letting stale evidence pass.
- **Live gates as bug finders**: the live parallel-feature gate failed three times, each on a genuine orchestration defect (§6). Fix, commit, rerun on the committed tree.
- **Billing guards at every layer** (env scrubbing, first-frame auth checks, per-step cost checks, pinned free models) — zero paid calls.

## 6. What went badly and why

- **Offline limits did not fit real work**: 60 s timeouts, 4,096-entry journal, 64 KiB frames, 1 MiB retained stdout, 1,024-file snapshots, 64 KiB stdin writes. Fixed with live-only overrides, streamed stdout, Git evidence, chunked writes.
- **Real Codex notifications carry `emittedAtMs`**; the strict offline schema would have rejected all live traffic. Schema widened.
- **Claude auto-updated 2.1.285 → 2.1.286 mid-session** and the exact pin locked it out. Now: later patch of the qualified major.minor accepted, installed version recorded and checked against the stream; prerelease pins (Codex) stay exact.
- **Live G06 failures**: (1) planner prompt biased toward a single node; (2) reviewers could review their own work; (3) an explicit `@alias` bypassed worker roles. All fixed with tests.
- **Memory pressure**: the laptop (16 GB) had ~2 GB free; Claude Code killed one gate run. Gates run 2 vitest workers plus many child processes.
- **PowerShell gotchas**: `R` is an alias (Invoke-History); `"\n"` is literal (broke a test file); `--` is swallowed by `npm.ps1`; pipes add a BOM. Prefer Bash or Edit for multi-line edits.
- **Windows command lines**: Node escapes `"` for `cmd.exe` badly — check commands need `windowsVerbatimArguments` with `cmd /d /s /c "…"`. OpenCode prompts go on the command line: capped at 24,000 chars.
- **Git ref nesting**: `xvant/<id>` cannot coexist with `xvant/<id>/<label>`; turn branches use `xvant-work/…`.

## 8. Decisions, rationale, and invariants

- **Trusted-local write profile**: workers use their own native tools inside XVANT-created worktrees; requires `profile: workspace-write` + `acknowledgedNativeBypass: true`. Read-only profiles stay **blocked** on external runtimes (native tool restrictions are not live-tested).
- **The user's checkout and branches are never changed.** Results land on `xvant/<id>`; `accept` records acceptance and prints the merge command; merging is the user's act.
- **Unknown outcomes never auto-retry**; only known failures get ≤2 repairs, and an identical repeated failure stops early.
- **Node-level acceptance is automatic by the host actor `xvant-orchestrator`** after host checks pass; **root acceptance is explicit by the user** and bound to the exact row version and integration head.
- **Billing**: no API keys ever; Codex must be `chatgpt`, Claude `apiKeySource: none`, OpenCode only `opencode/big-pickle` with cost 0.
- **Codex worker sessions get an explicit `mcp_servers` table** (XVANT's bridge or none) — never the user's MCP servers. Claude uses `--strict-mcp-config --setting-sources=project,local`.
- **UI renders all run/worker/repository text with `textContent`** (never `innerHTML`); strict CSP; no inline styles/scripts. Keep it that way.
- UI is dependency-free (no React/Vite build) — a deliberate deviation from the original plan for speed and supply-chain size; `playwright-core` (Apache-2.0, 0 deps) drives the installed Edge for E2E.
- Do not rerun source-bound gates while editing the tree (receipts fail with "Source changed").
