## Decisions, rationale, and invariants

- `OfflineCodexController.run(input, scenario, mode)` defaults to explicit `resume`; `create` reserves `pending:<connectionId>` until a validated reply binds its returned ID. No live executable is launched.
- `ProviderJournal.bindSession` is a trusted-host API, not protocol validation. It requires an open fenced connection, exactly one creation intent, no prior bind/run/turn dispatch, and a free native reservation. Worker session ID and reservation change atomically; schema remains v2 with optional JSON `sessionBound`.
- Resume excludes historical turns and validates the requested thread ID. Both modes require the registered workspace, pinned creation CLI version, idle thread, untrusted/user approval and read-only sandbox. These conservative constraints are offline-qualified only.
- Legacy transport-only lifecycle fixtures can still use a host-supplied loaded session. The owned controller always performs setup.
- Native errors fail closed even when `willRetry` is true. No retry, auto-resume, historical turn replay, paid fallback or automatic acceptance.
- Session-binding crash fixtures use the fixed peer, which exits on stdin EOF when its parent dies. This is not hostile-descendant containment.
- Generated bundle sources are from `.artifacts/codex-schema`; all 13 original source hashes matched before extension. Nineteen roots now pinned. Original schemas and definitions were checked unchanged.
