## Decisions, rationale, and invariants

- `Store.providers` is a trusted-host API, not a public HTTP command or provider capability. Only managed/offline records are admitted. A supplied transport writer is trusted to target the owned synthetic peer.
- Outbound frames contain prompt text and are private database/backup data. Inbound output/error bodies are discarded after delivery; only normalized envelope digest, size and routing metadata survive. This is an audit journal, not a replay queue.
- Each connection permits 4,096 journal entries and 64 KiB frames. IDs stay connection-local; durable connection identity and controller generation prevent reuse across restarts.
- Native completion stores completed/cancelled/failed but leaves task `needs_attention` and connection `result_pending`. Crash recovery marks open prior-generation connections unknown. Both states hold reservations until trusted reconciliation; no native acceptance exists yet.
- `finish` and `bindRun` must follow host-side protocol validation. The synthetic runner uses `CodexLifecycle` before calling them. Generic journal methods do not validate vendor messages themselves.
- Schema v2 is additive and automatic; verified snapshots retain v1 support and validate v2 provider PK/FK constraints. Do not downgrade a live database.
