## 2. Current task

The operator asked two things on 2026-11-01:

1. Does XVANT have a recursive self-improvement loop? **Answer given:** not an automatic one. It has a *supervised* routing loop (`npm run routing`): a benchmark report yields candidate model choices per role, and `promote` adopts one only if it beats the current default on held-out tasks, with a ledger and rollback. Nothing rewrote code, skills or prompts, and nothing learned from failures across runs.

## 5. What went well and why

- Keeping the graph host-written and labelling prompt text as *sourced data, not instructions* fitted the existing trust model (memory, packets) with no new policy.
- The full test suite caught that verified snapshots validate every table. Without the backup/restore fix, every v5 database would have been refused as `SCHEMA_UNSUPPORTED` on restore.
- Matching on a challenge's own identifying words (≥ 50% present in the query), rather than raw BM25 hits, keeps unrelated "tests failed" lessons out of prompts.

## 6. What went badly and why

- I told the operator that workers "can also query it themselves". That is untrue in practice: the tool is defined but not in any catalog (§10, §13 step 2).
- The first full suite run happened after PR #2 was opened. Run the whole suite before opening a PR, not only the affected files.
- The merge with `main` changed review semantics (`rejected` vs a missing verdict). The lesson code had to be adjusted to match, which is easy to miss in an auto-merge.

## 7. Dead ends already tried

- Showing lessons on a node's *first* attempt: rejected before building. Every objective shares words with some challenge, so it would add noise to every prompt. Lessons appear only once there is a concrete failure text.
- Counting the `[REDACTED]` placeholder as a matching word: it made unrelated redacted failures look similar. It is now a stop-word.

## 8. Decisions, rationale, and invariants

- **Only the host writes the graph.** A solution counts as verified only for host-run checks that passed. A worker's summary is labelled as its own account.
- **Challenge identity** = normalized first line plus the first "reason-looking" later line (numbers, hex, absolute paths replaced). The same failure in a later run updates one node.
- **Learning never fails a run.** Every lesson read or write is wrapped; errors are counted in `state.lessons.errors`.
- **Not judged:** unknown or cancelled turns, runtime failures (`status: failed`), operator stops, and reviews without a verdict.
- **Off switch:** `lessons: false` in `RootSpec`.
- Graph text passes through `redactSecrets` before storage. Defense in depth, not a guarantee.
- Handoffs stay off `main`. Committing `plan.md`, `docs/plans` or `.Codex` makes the offline gate receipt stale.

## 9. Assumptions made

- Lessons will raise repair success rates and cut tokens. **Unmeasured** (§13 step 3).
- Lexical matching (FTS5 + token overlap) is enough. Paraphrased review findings may not match.
- One shared project per surface is acceptable for now (§10).

## 10. Known issues

- **`lessons.search` is not in any catalog.** `NativeTurnRunner`'s `CATALOG` is `file.read`, `file.apply_patch`, `repo.search`, `git.inspect`, `test.run`. External runtimes use the MCP bridge with a fixed list. Only `tools-fixture` registers controller tools.
- **Node-level fixes from the CLI and the app are recorded as unverified.** `xvant run` and the app never set `RootSpec.nodeChecks`, so a node repair's solution has `checks: []` and half the ranking weight. Combined-check fixes are verified.
- **Lessons are shared across repositories.** CLI runs all use `projectId: 'cli'` and the app uses `'app'`, so a lesson from one repository can be shown in another.
- No curation: there is no command to delete, reject or edit a bad lesson. A bad lesson only sinks through usage feedback. There is also no size cap or pruning.
- Not visible in the local app (`xvant ui`).
- Lessons are not part of the memory import/export bundles (`packages/context/src/transfer.ts`). Backups do include them.
- **No CI.** The repository has no `.github/workflows`, so PRs get no check runs. All test evidence comes from a session running the gate by hand.
- Carried over from the previous handoff: reviews, a live soak and signing are open under Phase 10.
