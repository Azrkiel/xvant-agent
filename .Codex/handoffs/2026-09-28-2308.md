## 5. What went well and why

- Persisting intent before external effects makes crash uncertainty explicit and prevents blind duplicate work.

- Small committed slices and full offline gates kept the growing recovery surface reproducible.

## 8. Decisions, rationale, and invariants

### Authority and durability

1. The deterministic host/controller owns dispatch, permissions, generations and verification. Model output and native protocol metadata are data, not authority.
2. Command, state, event and dispatch intent commit together. Check ownership before migration/writes and again at relevant external-effect boundaries.
3. `workRevision` binds work; `rowVersion` handles optimistic state changes. Verification receipts retain exact task/attempt/artifact/hash bindings.
4. Worker output cannot mint trusted verification receipts. A provider completion does not accept a task. Explicit host-authorized review/acceptance remains separate.
5. Unknown execution outcomes never auto-retry. Cancellation requests, disconnects or terminal output alone do not release workspace/session reservations; trusted reconciliation must prove execution stopped and verification finished.
6. Preserve stale-generation rejection and lease fencing across startup, output, shutdown and acceptance.

### Provider boundaries

7. `fixture/claude-launch` is a persisted host descriptor, not a vendor RPC. Only the fixed fixture receives these serialized options today.
8. Claude creation reserves its final UUID directly. OpenCode retains an atomic provisional-to-returned identity transition. Do not unify these by inventing vendor behavior.
9. Codex uses a version-pinned JSON-line RPC projection; Claude uses a selected NDJSON/SDK projection; OpenCode uses selected SSE/event projections. OpenCode fixture traffic travels through pipes, not a qualified authenticated HTTP endpoint.
10. Current pins recorded in the README: Codex `0.158.0-alpha.2.1`, Claude SDK `0.3.283`, OpenCode SDK `1.18.33`. These are local historical pins, not claims of current latest versions or account compatibility.
11. Correlation includes host request and native session/message/run identities as appropriate. Idle, tool boundaries or clean EOF alone do not establish trusted completion; host-owned shutdown and verification also matter.
12. Permission paths are constrained/denial-only in these fixtures. Empty tools and plan mode are not proof of OS containment.
13. Imported/attached sessions are not automatically controllable. Authenticity/freshness of future qualification evidence must be enforced by the host, not supplied by an HTTP client or worker.

### Scope and user preferences

14. Subscription-first is intended; entitlement is unproven. No paid API fallback, vendor credential extraction, quota evasion or account rotation is authorized.
15. Keep live providers disabled until their own auth, billing, protocol, interruption and recovery probes pass. Do not silently enable live flags to “finish” a gate.
16. Windows trusted-local evidence does not establish Linux support or a hostile-code sandbox. Configured CI is not an observed pass.
17. Preserve both checkouts and local evidence. Plans/handoffs remain local; publishing is separate.
18. User prefers action within authorized scope and terse updates. Do not repeatedly request permission for already-authorized routine work. Do not spawn agents unless the user or applicable instructions explicitly authorize delegation.
