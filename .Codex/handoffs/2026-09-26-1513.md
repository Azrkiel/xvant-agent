## What went well and why

- Pure transition and graph functions enabled fast, deterministic offline tests and kept model/provider behavior outside the domain rules.
- Separate `workRevision` and `rowVersion` let state changes preserve valid evidence while edits invalidate it.
- A controller-owned dispatch identity, strict event validation, and controller-generated check receipts prevented worker output from approving itself.
- A simulated runtime exercised success and failure paths without subscriptions or model spend. The gate records exact local evidence instead of treating CI configuration as execution.

- The npm `node` wrapper needed a blocked lifecycle script. Installing pinned `node-win-x64@24.21.0` directly supplied the local binary. The first local npm launcher path was wrong; `.tools/node_modules/.bin/npm.cmd` worked.

- Vitest unpacked array fixtures in graph parameterized tests, so intended cases were not exercised. Strict TypeScript caught it; wrapping each graph in an object restored meaningful tests.
- Review found the adapter could mutate a shared request and change the expected event identity. A failing regression reproduced it; the controller now passes a cloned request and compares events with its own original identity.
- A parallel graph-agent attempt hit its usage limit. The graph implementation was completed in this session directly.

## Decisions, rationale, and invariants

- Phase 1 uses original XVANT contracts and simulated workers. Hermes and ECC are references, not runtime dependencies.
- The development baseline is Node 24.21.0, npm 12.0.2, TypeScript 6.0.3. TypeScript 7 was not selected because the installed typescript-eslint range ends below 6.1.
- All worker events are untrusted until validated; worker text cannot mint verification receipts. Receipts bind task, attempt, work revision, tree hash and artifact-set hash.
- Unknown/ambiguous dispatch outcomes never auto-retry. Preserve this through storage, crash recovery, and provider adapters.
- The controller sends adapters a copy of the request. Keep expected identity and durable dispatch intent independent of transport objects.
- The Phase 1 graph API validates up to 20 nodes and three parent levels; it does not schedule the graph. Phase 1 accepts only `simulated` runtime kind.
- `npm ci --ignore-scripts` was qualified only for Phase 1. Phase 2 native SQLite may need a reviewed, explicitly allowed build/install step.
- Provider-native session IDs may not fit XVANT's bounded internal ID grammar. Qualify and map them, rather than weakening internal IDs blindly.
