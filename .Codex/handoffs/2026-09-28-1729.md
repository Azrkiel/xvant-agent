## Decisions, rationale, and invariants

- Existing host-selected sessions only. Claude initialize handshake precedes fixture start; matching system/init metadata follows start and must precede other native messages. SDK pin 0.3.283 and CLI fixture version 2.1.283 are separate.
- Claude setup requires a valid response with empty pending permission/dialog arrays. Metadata must match session/root, plan mode, no tools/MCP/plugins and no plugin errors. apiKeySource none does not establish billing or account qualification.
- OpenCode GET session descriptors validate response ID, root directory and unarchived time data. The fixture wraps HTTP replies with fixture:http-response plus request ID/method/path/status/body inside its pipe. This is not an HTTP client, native SSE event or endpoint authentication.
- Claude interrupt sends cancel_queued:true only after interrupt_receipt_v1 and interrupt_cancel_queued_v1 are advertised; still_queued must be empty and cancelled IDs must belong to this request. OpenCode abort requires a correlated true success response.
- Acknowledgement alone never establishes cancellation. Require terminal message, no pending denial writes, complete EOF and successful owned process shutdown. Cancelled outcome retains reservations and cannot enter verification/acceptance. Unknown replies never replay.
- The offline run scenario drives interruption. Public live interrupt API is still open; stop() is emergency process cancellation. Native session creation/resume launcher semantics remain open.
- Terminal native message ID still occupies nativeRunId in shared evidence; attemptId binds the host invocation. Do not label message IDs as vendor turn IDs.
- No live SDK/HTTP launch, credentials, paid fallback, Linux qualification or hostile-code containment.
